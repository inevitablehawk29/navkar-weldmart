## Deployment checks that require the owner's environment

1. Set the three required enquiry variables and verify the Resend sender domain. Add Upstash credentials for distributed rate limiting. The code currently fails open if Redis is unavailable, so monitoring and provider-side protection remain important.
2. Submit one real enquiry through each form after deployment. Confirm lead inbox receipt, customer confirmation, and failure messaging if email delivery is interrupted. Build success alone does not prove delivery.
3. Review the Terms page's 15-day quotation, payment, minimum-order, and liability claims with the business owner. These are business commitments and were not inferred or rewritten here.
4. Check Search Console and real-user Core Web Vitals after deployment. No field dataset or production analytics access was provided, so LCP, INP, and CLS cannot be asserted from this code audit.
5. Verify testimonials, client names, project counts, and partner-logo permissions against business records before publishing changes to those claims.

## Research used

- [Google Local Business structured data](https://developers.google.com/search/docs/appearance/structured-data/local-business): keep business details accurate and avoid invented location coordinates.
- [Google canonical URL guidance](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls): sitemap and canonical URLs should be consistent.
- [web.dev Core Web Vitals](https://web.dev/articles/vitals): measure LCP, INP, and CLS at the 75th percentile of real visits; this audit does not substitute for field data.
- [W3C form error notifications](https://www.w3.org/WAI/tutorials/forms/notifications/): errors should be communicated in text, close to the relevant form.

## Dependency refresh — 27 September 2026

- Updated the lockfile's compatible dependency tree, including Next.js and its matching tooling from 16.3.1 to 16.3.6. The direct Next.js minimum is now `^16.3.6` because the older installed release had two critical advisories.
- Updated React and React DOM to 19.3.0, React types to 19.3.0, and Node types to the Node 22 line used locally. Other compatible packages moved to their latest allowed releases.
- Attempted ESLint 10.11.0. `npm run lint` failed in `eslint-config-next`'s React rule (`contextOrFilename.getFilename is not a function`), so ESLint was restored to 9.39.5. The lint command then passed. ESLint 10 should be reconsidered only when the plugin chain supports it.
- Deferred Framer Motion 13 and TypeScript 7 because they are major upgrades without a need to resolve an advisory. `@types/node` 26 was also left aside because the app is checked on Node 22.
- `npm audit` and clean `npm ci` both report zero vulnerabilities. `npm run build` and `npm run lint` pass. Twelve sampled production routes returned HTTP 200.
- npm warns that the current `@react-email/components` 1.0.12 package family is deprecated, but it is also the latest version published under those package names. Migrating the email templates to a different package should be done with live email rendering and delivery verification.

[Next.js September 2026 security release notes](https://nextjs.org/blog) and [React 19.3 release notes](https://react.dev/blog/2026/09/09/react-19-3) informed the targeted upgrades.

## UI and conversion improvements — 27 September 2026

A responsive review of the homepage, contact page, projects listing, and service area found the following opportunities. The changes below are implemented in this branch:

- The mobile homepage placed the two primary actions low because its metrics were stacked vertically. The metrics and actions now sit in compact rows, with a clearer description of steel structures, custom metalwork, material supply, and service area.
- The mobile contact page placed four contact-method blocks ahead of the enquiry form. The form now follows the introduction; direct contact options follow the form. Desktop retains the side-by-side layout.
- The contact form used two narrow columns, small controls, and limited browser autofill hints on phones. It now uses one column on phones, larger controls and labels, phone/email input types, and autocomplete tokens. The footer form received the same input-purpose hints.
- Service links had a small text-only tap area. Each service tile is now one large, clearly bounded link with a visible keyboard focus state.
- Featured-project carousel arrows were off to the desktop side and hidden on mobile. They now appear beneath the carousel at both sizes, with 48px controls and a mobile swipe hint.

Research basis: [NN/g B2B website usability](https://www.nngroup.com/reports/b2b-websites-usability/), [NN/g form design](https://www.nngroup.com/articles/web-form-design/), [web.dev form design](https://web.dev/learn/forms/design-basics), [W3C input-purpose guidance](https://www.w3.org/WAI/WCAG22/Understanding/identify-input-purpose), and [WCAG 2.2 target-size guidance](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum). These are design principles; no conversion uplift is claimed without analytics or user testing.
